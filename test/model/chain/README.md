# Model chain tests

Здесь живут тесты реальной модели, которые стартуют не с начала задачи, а с сохранённого состояния workflow.

Цель: зафиксировать вход в конкретный шаг/границу цепочки и проверить структурный контракт результата, не сравнивая формулировки текста дословно.

Следующий основной fixture: состояние `/status` после retrieval (перед `understand`) и состояние после `understand` (перед `prepare-change`).
