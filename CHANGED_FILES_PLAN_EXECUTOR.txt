PlanExecutor refactor

Core change:
- TaskPlan is now the sole owner of execution routing.
- OperationResult.nextOperation is intentionally ignored by PlanExecutor.
- AgentRuntime is reduced to lifecycle concerns: start, pause/resume, finish, metrics.
- PlanExecutor executes semantic plan steps with per-step attempts and recovery.
- Recovery can retry, insert steps, skip, request human help, or fail.
- TaskPlan now has a version number; structural recovery insertions increment it.
- Added plan-aware console reporting (current plan node and attempt).

Changed/added files:
- src/agent/Planning/PlanExecutor.ts (new)
- src/agent/Runtime/AgentRuntime.ts
- src/agent/Planning/TaskPlan.ts
- src/agent/Planning/PlanGenerator.ts
- src/agent/Planning/PlanUpdater.ts
- src/agent/Reporting/ExecutionReporter.ts
- src/core/Nodus/Nodus.ts

Compatibility:
- Existing Operation profiles remain available as execution primitives.
- Legacy nextOperation/allowedTransitions fields are not used for TaskPlan routing.
- No configuration changes required.
