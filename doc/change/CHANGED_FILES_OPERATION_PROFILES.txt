Operation profile / prompt composition refactor

Goal
- Keep model-call settings generalized but close to the code that owns the call.
- Separate prompt behavior from model generation settings.
- Remove the central PromptRegistry from runtime wiring.
- Make prompt sections composable instead of constructing monolithic system strings ad hoc.

Main changes
- Added src/model/Profile/ModelCallProfile.ts
  - prompt: identity / purpose / rules / contextRules / returnFormat
  - model: temperature / maxTokens
- Added src/model/Prompt/PromptComposer.ts
  - composes the common identity + explicit prompt sections.
- OperationProfile now groups:
  - prompt
  - model
  - execution
- Default operation profiles keep their own rules and temperature next to operation configuration.
- PlanGenerator keeps TASK_PLAN_PROFILE next to planner code.
- RecoveryController keeps evidence/satisfaction/recovery profiles next to recovery code.
- Removed runtime PromptRegistry / PromptProfile / DefaultPromptDefinitions.
- Added shared OperationResult return-format text.
- Common system prompt no longer incorrectly requires JSON for RAW edit-file responses.

Important design choice
Return format is a prompt section, while the parser remains runtime-owned. Shared OperationResult JSON format is defined once; edit-file supplies its dynamic RAW format at invocation time.

Tests
- test:prompt:contracts updated for grouped operation profiles.
- test:operation:profiles added to ensure runtime no longer wires PromptRegistry.
